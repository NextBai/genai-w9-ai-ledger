題目：用 AI Coding 出一個記帳的網站
311949 白東衢　·　2026-11-16

一、專案主題

我請 AI 幫我寫出一個「記帳網站」。網站名稱為「AI 記帳本」。使用者可以輸入一筆收入或支出，存入瀏覽器本地儲存；也可以刪除紀錄。網站另有「本月統計」頁面，自動彙總當月收入、支出與結餘，並依分類列出金額，作為月報表。

二、使用哪個 AI 工具做 Coding

我使用 Claude（Anthropic 的對話式 AI 助手）作為 AI Coding 工具。流程為：我先寫好規格書 AGENTS.md，再把它貼給 Claude，要求它一次生成整個網站的檔案。此做法符合本週課堂所學：先給 AI 明確的規格與限制，再讓它產出程式碼，而不是請它随便發揮。

三、我的 AGENTS.md 寫了哪些內容

AGENTS.md 是我提供給 AI 代理的「規格書與工作規則」，放在倉庫根目錄。內容共分五節：

  1. 專案目標：一句話說清楚要做什麼——純前端記帳網站，支援新增、刪除收入／支出紀錄，並產生本月統計報表。
  2. 硬性技術限制：只用 HTML、CSS、原生 JavaScript；禁止框架、打包工具與後端；資料一律存 localStorage；每個檔案不超过 250 行。
  3. 檔案結構：指定 index.html（記帳主頁）、stats.html（月報表）、assets/（CSS 與 JS）的目錄配置，AI 不得自行增減。
  4. 功能驗收清單：逐條列出可測試的行為，例如「金額欄位輸入非數字時須顯示錯誤訊息且不得存入」、「刪除紀錄後統計數字須同步更新」。
  5. AI 工作規則：要求 AI 對不確定之處先問不要猜、不得偷偷擴大範圍、修改後必須回報 diffs 摘要。

四、實際讓 AI Coding 的過程與踩坑

成功案例：把 AGENTS.md 貼給 Claude 後，第一次生成就產出可運行的網站，新增、刪除與月統計功能皆正常。

踩到的坑與解法：

  1. 日期預設值錯誤：AI 生成的表單以 new Date() 直接當日期值，格式含時間造成存入後月統計比對失敗。解法：把此事寫回 AGENTS.md 驗收清單（「日期欄位須為 YYYY-MM-DD 格式」），再請 AI 修正——規格先行，AI 修得比對話來回快。
  2. 範疇膨脹誘惑：AI 主動提議加入圖表與匯出 CSV 功能。因超出本週作業範圍且違反「每個檔案不超过 250 行」限制，依 AGENTS.md 第 5 節規則要求它維持原範圍。
  3. 本地儲存鍵名不一致：兩個頁面各用不同 localStorage 鍵名，造成主頁存入的資料在統計頁看不到。解法：在 AGENTS.md 明文規定統一鍵名 aiLedger.txns。

五、成果驗證

  • 本地以 python -m http.server 實測：新增 3 筆支出、1 筆收入後刪除 1 筆，本月統計的收入、支出、結餘與分類金額全部正確。
  • 已推上 GitHub 並開啟 GitHub Pages，公開網址见第一节表格，手機與桌機瀏覽器均可開啟使用。

六、小結

本作業讓我體會：AI Coding 的品質取決於規格的品質。AGENTS.md 寫得越具體（限制、結構、驗收清單），AI 第一次就做對的機率越高；出錯時把教訓寫回規格書，比在對話裡反覆糾正更有效率。
